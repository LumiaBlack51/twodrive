# Linux 百度与 iCloud 挂载目录索引

文件管理器重新进入已访问目录时，应先得到当前挂载的本机元数据，而不是因五分钟显示缓存过期重新等待网盘。Linux 百度与 iCloud 现在共用 `Bridge::start_indexed`：保存成功、完整且验证过的根目录及访问过的子目录，按需在后台刷新。

## 行为与范围

- 沿用64个目录、100000个条目的总预算和LRU；根目录保留，其他目录在预算不足时淘汰。没有递归扫描整盘，也没有保存跨重启的数据库。
- 30秒后访问触发合并后台刷新，失败后沿用10秒重试间隔。刷新失败或返回无效列表保留上次成功的内容，成功的空列表正常替换旧列表。
- HEAD/PROPFIND属性预检和目录枚举共享一次浅层父目录读取。中文、空格、井号及字面百分号路径只解码一次。未缓存目录及被淘汰目录首次仍需联网；没有旧父身份依据时需要保守重新验证子目录。
- 父目录确认子目录删除、类型变化或身份更换后，清理对应子树，并用代次保护拒绝更早开始的子目录结果。父目录已淘汰、无法证明原身份时也不继续沿用孤立子树。
- 目录索引仅供显示。真实GET、范围读取、正文完整性和修改版本/权限仍检查实时状态；修改仍使显示索引失效，停止挂载不再服务旧索引。

最新云端变化可在后台刷新完成后的目录读取中出现，离线显示的是上次验证成功的内容。此实现没有承诺首次连接或首次访问未知目录可以离线完成。

## 编辑与原有实现

本分支同时包含此前在本机验证的iCloud Office临时锁队列及缓存清理修正，它们是当前挂载实现的一部分。小型新建临时锁先持久化本机，后台按原版本保护上传、清理；不接管既有云端锁，不在不确定的云端响应后盲目重放。百度仅使用目录索引，普通内容及Office锁文件仍按同步版本确认处理，不宣称服务端原子条件上传。

## 验证

旧根目录专用模式下，将实际存在的父子快照都老化超过五分钟，合成云端读取失败后，子目录PROPFIND返回503；新增回归期望保留已验证列表并返回207。初始测试的编码生命周期和根种子未包含子目录等夹具问题已修正，没有将编译错误或夹具缺项计作旧产品失败。

实现覆盖慢/失败刷新、空列表与无效列表、嵌套属性读取去重、实时正文、父目录删除/替换、在途子结果失效、孤立子树及索引预算；百度同步锁写入另有回归。实际合成FUSE还验证过期后的四种特殊字符子目录在云端刷新被阻塞时及时枚举，并保留已有quota/独立正文读取隔离检查。

本机挂载及最终PR源码验证结果见[TD-20261105-01](incidents/TD-20261105-01.md)。真实账号检查只读取目录元数据；测试、运行状态、凭据、私人目录名和抓包留在本机，不进入源码提交。

原源码与干净PR检出均为库135项、桥HTTP13项及显式纯合成FUSE2项通过，6项默认忽略；格式、严格Clippy和release构建通过。本机已安装，实际Nautilus在等待310.732秒后重新访问两家的根及子目录，共捕获226项调用，四个范围均完成目录枚举。单次调用最大约4.218毫秒，两个子目录分别约0.877/0.614毫秒；这些不是整窗渲染时延。首次未缓存子目录采样仍约0.393/5.100秒，不能用已访问目录的索引收益承诺所有首次访问都立即完成。
