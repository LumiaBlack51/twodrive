# 局域网存储协议分阶段方案

2026-11-07。本轮实现范围及验收见 [SMB 只读指南](smb-readonly-dev.md)。以下都是后续设计，未实施；每阶段须另获用户授权，不因已有库提供写函数就开放能力。

## 阶段 1：SMB 只读验收与平台补齐

先解决默认 Samba/旧 NAS 的可验证 no-follow 能力边界，不能以伪造能力位开放透明链接。保留手动 server/port/share/root/account/domain 配置；先在候选版本验证独立 Windows 共享和至少一种实体 NAS 的 Unicode、大小写、权限、强制签名/加密、取消、链路中断及根范围。用专门合成共享，不能扫描用户 NAS。补 Windows Python/私有凭据 ACL、所属进程崩溃回收和组件离线打包/许可证/摘要校验，再决定正式分发。无自动发现，不改 TwoDrive QUIC 发现。

## 阶段 2：SMB 写入（先手动，能力逐项验收）

| 操作 | 所需保证和恢复设计 |
| --- | --- |
| 新建 | 服务端 `FILE_CREATE`/create-only；已存在必须失败。临时同共享对象流式写入、flush、验证后安全无覆盖发布，目标竞争不得静默改名或覆盖 |
| 覆盖 | 先确认服务端是否能在同一事务/受保护句柄上检查版本并替换预期对象；**先 stat 后覆盖不是原子条件写入**。没有可证明的 CAS 时只提供明确标注的手动编辑及恢复副本，不能声明 conditional_upload |
| 移动/改名 | 区分同目录、跨目录、大小写变更、文件/目录；使用绑定对象的句柄及服务端 no-replace 语义。目标碰撞/跨共享不是普通原子移动；保持源与本地恢复材料 |
| 删除 | 普通删除/回收能力需明确，永久删除和清空回收站另行授权。绑定对象与预期状态，拒绝根删除和旧 ID 删除替换对象；断线后确认对象是否仍在，不能以路径缺失单独证明某个删除成功 |
| 并发与冲突 | 本地写意图、源散列、目标对象/版本与 session binding 先落盘；远端改变、锁冲突、权限变化都保留本地内容。SMB share modes/leases 不是跨掉线持久 CAS 或不可变版本 |
| 断线后结果未知 | 记录未确认提交，重新确认账号/share/root/对象身份和已提交内容散列；不能盲目重放 rename/delete/overwrite。无法确认则停止并给恢复选项 |
| 恢复 | private durable journal 绑定 profile/schema/revision/account/share/root，防止旧缓存跨连接上传；覆盖崩溃前后、分块完成后响应丢失、对象替换和根变化 |

只有原子条件覆盖、create-only、取消及不确定结果恢复都满足既有合同，才讨论 `conditional_upload`、自动备份或可写挂载。先解决 [基线审计](smb-readonly-dev.md#main-修复的机制核对) 的相关公共写入/缓存缺口，不把只读候选当作已经具备安全同步引擎。

## 阶段 3：SFTP 只读

选成熟 SSH/SFTP 库，先比较 Linux/Windows 支持、取消、文件属性、链接、认证和许可。手动 host/port/root/account，私钥/口令进入私有凭据组件。严格校验主机密钥：未知主机必须展示算法/指纹，由用户经可信渠道核实后明确保存；主机密钥改变必须停止，不能自动接受、静默刷新 known_hosts 或跳过校验。host/port/account/root/主机密钥版本绑定会话和缓存。先限定 realpath/root、拒绝链接逃逸；实现目录、stat、流式读取和取消后再验收写入。SFTP 不等于 SSH shell，不执行服务端返回的命令。

## 阶段 4：按实际设备需求决定 FTP/FTPS

先收集必须支持的设备与能力，再决定是否实现。优先显式 TLS 的 FTPS（AUTH TLS），证书链/主机名校验、受保护数据通道、禁止失败降级；兼容隐式 FTPS 时独立说明端口和握手。被动数据连接不得连接服务端指定的任意不可信目标，主动模式默认关闭。明文 FTP 必须在界面明确告知账号/内容未加密风险，由用户显式选择；不自动重试到明文。FTPS 是 FTP over TLS，与 SFTP（SSH File Transfer Protocol）互不替代。旧服务的 LIST 编码、MLSD/mtime 精度、路径/链接和弱版本要单独验收，先只读，不提供未经保证的条件写入。

## 阶段 5：NFS 可行性评估

比较用户态原生客户端与访问**用户已经挂载**的目录。前者需评估 NFSv3/v4、RPC/认证、锁/租约、UID/GID 映射、root-squash、ACL、缓存一致性、可取消 I/O 和 Linux/Windows 支持；不因一个 POSIX 文件操作成功就宣称所有语义成立。

已挂载目录方案可用受根目录限制的本地文件 Provider，但服务端 UID/GID/权限、属性/数据缓存、软硬挂载时阻塞和重连由 OS 挂载管理；该方式必须标为“访问已挂载目录”，**不能宣传为原生 NFS 支持**。不自动执行 mount、提权、修改 /etc/fstab、防火墙或系统服务。对挂载消失/被替换、本地链接和范围变化实施身份重验，先只读验证后再决定任何写入。
