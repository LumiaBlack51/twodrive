> 历史设计：2026-10-29 用户改为默认可编辑，取消本机密码及模式切换。当前行为与验证见 [默认可编辑](default-editable-2026-10-29.md)。下文保留此前实现及调查上下文，不再是新版操作步骤。

2026-10-28 开发预览。用户要求 OneDrive、iCloud、百度的客户端和 D 盘挂载都能选择只读/可编辑，并在修改前增加密码或锁。默认保留原权限；没有解锁的连接不允许写入。

## 使用与保护范围

在每张连接卡片的“只读 / 已锁定 / 可编辑”按钮中调整权限。首次选择可编辑，设置至少八个字符的**本机写入密码**；以后使用该密码解锁指定网盘。无需提供网盘密码，密码不发送给网盘。解锁同时允许客户端上传、创建目录、改名、删除，以及对应 Windows 挂载的写入。可随时选择“立即上锁”或改为只读；切换会正常卸载、重建该连接及挂载，保持其他网盘和浏览选择。

这是防止误操作的本机访问锁，不是云端权限或缓存加密。密码使用随机盐和 PBKDF2-HMAC-SHA256（600,000 次）校验，Windows 上校验记录由现有 DPAPI 私有文件保护。密码不在公开 profile、日志或命令行中回显。解锁许可绑定客户端运行代次、profile 和 revision；重启重新锁定，可继续自动连接和只读挂载。不能通过直接保存 `writable=true` 绕过解锁。

保存前请关闭正在编辑的文件。有尚未上传的挂载内容时，普通卸载、权限切换和退出会被拒绝，并保留内容。客户端异常退出后，下一次启动仍只读挂载；缓存不自动跨越写入锁。解锁后的恢复继续核对原版本，冲突不会强制覆盖。

## 三种网盘的写入语义

| 网盘 | 手动编辑 | 覆盖保护 | 自动文件夹备份 |
| --- | --- | --- | --- |
| OneDrive | 解锁后可用 | 保持既有 create-only / expected-version 条件上传 | 仍受原能力及备份配置限制 |
| iCloud | 解锁后可用 | 写前核对快照；持久保存原文件及待写内容；上传后重新下载并核对 SHA-256 | 未开放 |
| 百度 | 解锁后可用，受应用授权目录和平台权限限制 | 写前核对；4 MiB 分片和分片 MD5；提交前再次核对；原文件副本及上传后完整 SHA-256 核对 | 未开放 |

用户已选择接受后两者的普通编辑方式。它们仍明确返回 `conditional_upload=false`，不会伪装成原子条件覆盖，也不进入自动备份。界面使用单独的 `manual_upload` 能力。iCloud 由已绑定、加密配置的官方 Rclone 执行；Rclone 的覆盖路径会先把旧对象移入废纸篓，因此必须先完成本机恢复副本。百度的版本管理参数不等于 expected-version 比较；新建使用冲突失败策略，覆盖使用 `rtype=3` 并保留平台版本。

远端不提供原子版本覆盖时，其他设备恰好在最后核对与提交之间修改，仍可能发生竞态。本机副本保留的是本次写前读到的版本，不能承诺包含竞态期间其他设备的最后修改。非空目录的删除在这两个适配器中拒绝，需先处理其中内容。应用授权或服务端配额拒绝时显示失败，保留副本。

## 挂载与恢复

原 D 盘路径继续分别使用 `D:\TwoDrive\OneDrive`、`D:\TwoDrive\iCloudDrive`、`D:\TwoDrive\Baidu`。Rclone 原生文件系统组件只得到随机认证的私有回环 Provider 桥，不持有云端凭据。解锁后启用持久完整 VFS 缓存及关闭句柄时同步回写，支持随机位置写入。读模式仍复用已有校验缓存。

持久缓存按 profile **和账号 binding 的摘要**隔离；账号变化不能重放旧账号内容。桥保留首次观察版本，并在自身成功修改子项后更新父目录版本；背景刷新不会授权旧编辑覆盖新版本。所有写入先接收到私有文件，未收齐内容不会提交。读取和写入继续受到暂停、账号与权限许可检查。目录写入使用同一 Provider 合同，无网盘类型分支。

“设置 → 文件管理器挂载 → 打开写入恢复目录”提供恢复入口。`before.bin` 为原文件，`edited.bin` 为失败的编辑副本；桥的 `.content` 是接收内容，配套 JSON 记录原路径和状态。VFS 的待写缓存也保留。应先复制到其他位置，再按记录恢复文件；副本不会被普通缓存清理删除，成功覆盖后原文件副本也保留，因此会占用本地空间。不要把存在本地缓存等同于云端已保存。

## 验证与交付边界

本地回归包含独立账号写入、随机位置修改、创建/改名/删除、GUI 上传、密码拒绝、重新上锁、重启只读、冲突拒绝卸载/退出、异常结束后恢复副本保留。原生检查使用真实 WinFsp 与独立回环 WebDAV 服务，不使用用户账号或 D 盘目录。另有百度模拟官方接口的跨分片、原版本核验和失败副本检查，以及桥的中断上传和版本持久化回归。

本地 123 次默认 Rust 测试执行、78 项 Flutter、严格 Clippy、分析与 Windows release 构建通过，5 项组件测试默认忽略不计入执行数。release 引擎的 7 组真实 WinFsp 检查通过，另有既有只读挂载 5 组、启动恢复 6 组及本地 IPC/签名发现/QUIC 配对写入回归通过。包校验及部署结果在交付后追加。**尚未对用户真实 OneDrive、iCloud、百度进行写入验收**；必须由用户在新界面设置密码并用专门的小文件验证。没有向用户真实网盘写入测试文件，也没有改动原账号凭据。
