# iCloud Drive 本机预览接入

本版本在现有 Development GUI 的“添加连接”中注册 iCloud Drive。协议和认证由独立 Rclone 组件完成，Flutter 消费同一 Provider schema/能力和 IPC，不访问 Apple API。未采用 iCloud for Windows 的本地同步目录。新增的 [Windows 只读文件夹挂载](windows-readonly-mount.md) 通过现有 Provider 合同、本机受保护的只读桥和 WinFsp 实现；原有多网盘包没有该挂载。本机已安装 WinFsp 并部署挂载版，合成本地数据的真实 Windows 文件系统检查通过；原 iCloud 登录自动恢复，用户亲自挂载后反馈 iCloud 可用。该反馈未细分文件打开/复制，不扩大为独立文件字节或大文件验收；同时发现的 OneDrive 根目录故障另见 TD-20261028-14。

当前实现浏览目录和手动下载。上传、覆盖、新建、移动、删除、同步和备份保持关闭。文件 ID 被封装为绑定登录代次、路径、对象 ID、大小和元数据版本的快照；下载前后再次检查快照和大小。这个元数据指纹不能替代服务端强版本或原子条件写入，同 ID/大小/时间戳的内容变化仍有边界，不能用于生产同步完成证明。

## 登录和使用

1. 运行完整预览目录中的 TwoDrive，选择“连接 → 添加连接 → iCloud Drive”。
2. 和其他网盘一样，在同一连接表单直接填写 Apple 账号和遮挡的密码，点击“登录 iCloud / 更新授权”或“保存”。仅双重认证需要时另行提示输入验证码。Drive 和普通组件配置自动处理，无需输入命令。不要把密码或验证码发到聊天中。遇到账号安全限制时保留原设置，不自动更改 Apple 安全选项。
3. 登录成功后点击“保存并连接”；直接点“保存”启动认证时，完成后会自动保存并连接。已有连接首次点“登录并使用”进入同一账号密码表单。取消保留原账号配置；凭据输入仅用于本次认证，不写入连接 profile，私有加密配置由协议组件维护。
4. 连接后浏览目录并选择文件下载。重新授权前先断开该账号。过期认证、信任设备和高级数据保护的实际兼容性需要真实账号验证。

图形登录不启动终端或第二个托盘客户端。技术诊断时仍可手动使用可选的终端助手：

```powershell
./twodrive-provider-login.exe --state C:\YOUR_PRIVATE_DIRECTORY
```

手动助手和 GUI 必须使用同一私有目录。该目录仅用于本工具，不能指向其他客户端配置或真实文件缓存。高级目录由适配器创建，普通连接不需要编辑它。

更新已有客户端应保留原 Development state 和已保存的 OneDrive 连接，退出旧进程后再使用新包，不并排启动第二套日常客户端。Windows 的不同显式 `--state` 目录允许隔离测试；同一规范化目录仍保持单实例。该能力用于测试，不代表更新需要另建账号配置。

## 凭据和进程边界

- 随机配置加密密钥经现有 private_file 保存；Windows 使用当前用户 DPAPI，Unix 使用私有文件。Rclone 配置保持加密，刷新仍写回同一配置。密钥通过子进程环境传递，不出现在命令行或公开 IPC。
- 每个配置有独立目录和登录代次。连接期间持有认证共享锁，重新授权/退出需要独占锁；读取操作另有串行锁。恢复 worker 必须匹配原登录 binding。
- GUI 认证在独立加密暂存配置中进行，原配置只在认证及根目录读取成功后原子替换。每个问题绑定一次性 attempt，原始组件状态经 private_file 保存；取消删除所属临时配置。密码默认值和协议错误正文不返回 UI。
- 认证组件仅在操作期间开放 OS 分配的 `127.0.0.1` 端口，使用随机控制密码和禁止代理/重定向的本机请求，结束或取消即终止回收。真实密码随本机 HTTP 请求体传递，不出现在命令行、明文临时文件、公开 status 或日志中。
- GUI 密码回答先通过组件的 `core/obscure` 转换再交给配置状态机；`opt.result` 不会自动执行普通参数的密码转换。此格式转换不代替整个配置文件的加密。认证和首次目录验证使用本次表单的网络路由，后续验证码步骤固定沿用原路由。
- 失败提示只返回固定的脱敏类别及组件 HTTP 状态，不返回原始 RC 错误正文（其中可能含请求凭据）。`AUTH_FORMAT` 表示客户端格式问题，`AUTH_NETWORK` 表示连接失败，`AUTH_DENIED`/`AUTH_SECURITY` 表示组件返回对应的账号拒绝/安全限制，`AUTH_REMOTE` 表示原因仍未知。密码提交后清空，保留账号输入供重试。
- 使用固定的 iclouddrive 类型，拒绝其他后端及自定义认证端点。读取子进程不接收用户输入，不弹认证；标准错误不直接转发，输出/项目数量和时间均有预算。下载使用有界分块，取消或失败后回收所属子进程。
- 同账号操作按跨进程文件锁串行等待，识别平台原生争用错误（包括 Windows 错误 33），45 秒后明确超时。内容下载和 GUI 目录刷新等待锁时都检查请求取消；退出先取消显示用的目录刷新及容量读取，Rclone 子进程轮询取消并由所属调用回收。完整索引等旧后台接口仍使用其自身预算。真实账号验证脚本先检查账号是否被客户端使用，在用时拒绝发出云端请求；测试期间避免重新连接该账号。
- 退出登录移除本地加密配置及密钥，保留下载和缓存，不删除云端文件。临时认证失败不会自动清理凭据。

## 本机验证状态

### 容量显示与同时连接

托盘标题旁下拉箭头可选择已保存网盘；已连接的其他账号保留会话，文件传输始终绑定原账号及配置代次。连接页显示横条，托盘用小环形图列出总量、已用、剩余；数值是整个 Apple 账号额度，可能包含照片和邮件，不等于 iCloud Drive 文件总大小。

Rclone 1.75.2 的 iCloud 后端未提供 `about`。容量查询只在现有登录有效时，从加密配置读取现有 Cookie，在固定 `setup.icloud.com` 的 `storageUsageInfo` 接口发出只读 GET；不解码密码、不重新登录、不扩大文件写入能力、不接受自定义端点或重定向。Cookie 和账号内部标识不返回 UI、日志或公开 IPC。配置读取使用同账号操作锁，网络请求连接超时五秒、总超时十五秒，响应有大小限制；失败不改变文件连接。解析/脱敏及本地多连接回归通过，用户在更新后的 GUI 明确反馈容量显示与切换正常；没有记录各账号具体数值或独立比对精度。此接口不是 Apple 对第三方承诺稳定的公开 API，失败时界面明确标为暂不可用。参考 [PyiCloud 账号接口实现](https://github.com/picklepete/pyicloud/blob/master/pyicloud/services/account.py)。

本轮更新详情及新旧验证边界见 [多网盘验证记录](multi-cloud-2026-10-28.md)。以下保留此前登录和读取的实际记录，不将它们作为新增容量和多网盘的真实验收。

本机验证结果随实际新包更新记录；包括 Rust 严格 Clippy、86 次默认测试、三个显式官方组件测试（加密、读取、取消、图形问题桥、密码格式、过期步骤和保留原配置），以及 50 项 Flutter 测试、静态检查和 Windows release 构建。密码格式回归在旧传递方式下失败，修复后通过，测试停在高级配置问题前，不向 Apple 提交模拟凭据。真实 Windows 锁等待回归也已证明旧代码失败、修复后通过；另有 Python 保护检查和当前 GUI 实际锁的本地验证。

authfix 包由用户亲自登录成功，实际保存的登录通过根目录读取、一个 1,117 字节既有文件两次相同下载、元数据快照、本地禁止覆盖及无提示重连，云端写入零。该后台验证同时干扰了用户 GUI，单独记为锁并发缺陷并修复，不将上述读取证据视为并发使用通过。锁修复后本轮只运行本地回归，避免再次干扰用户。Linux 运行/挂载、认证过期和 ADP 兼容性未验收。
