# TD-20261106-01 桌面空闲时反复扫描挂载状态

每三秒的界面定时器请求状态，挂载缓存统计随后解码全部云端文件记录。已选账号的缓存还会在状态聚合后计算第二次。即使窗口已隐藏，定时器也可能读取当前文件夹并查询网盘容量。

状态读取改为由打开窗口、切换页面、主动刷新和操作事件触发。文件页按需读取目录，托盘和连接页读取状态及容量。窗口关闭后，等待中的状态回复会跳过已离开的文件页。后台备份和挂载由其现有任务调度。后台进度快照随打开页面或手动刷新更新，客户端内的传输继续接收引擎进度事件。

SQLite 部分索引仅覆盖有缓存路径或处于待处理状态的记录。状态页复用账号汇总中的缓存结果，恢复和同步仍可读取完整清单。

旧版在空闲回归的 3.3 秒内发出状态和目录请求。新版同一时段保持静默。回归也覆盖页面打开、关闭、缓存和待处理状态，以及 SQLite 查询计划。验证使用隔离状态和合成数据。

上一份 PR 的自动检查暴露了两个独立的校验问题。临时锁测试改用由应用创建的私有子目录，消除对运行器 umask 的依赖。仅在非 Windows 分支使用的挂载辅助函数按相同平台条件编译。

PR #2 的首次自动检查发现，独立 CFAPI 包编译了共享 Linux 测试，但其测试包没有直接依赖 libc。FIFO 夹具改用系统 mkfifo，后续 Clippy 报告的测试断言使用 is_none。隔离 CFAPI 的 28 项测试和严格 Clippy 通过。文件页在排队的读取开始前关闭时，也会跳过状态请求，相关 8 项客户端回归已复测。
