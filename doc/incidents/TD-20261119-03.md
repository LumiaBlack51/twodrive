# TD-20261119-03 / 04：Linux DAV 冷挂载导航与状态角标

- 日期：2026-11-19
- 影响环境：Nautilus 46.4 与 TwoDrive DAV 的 iCloud、百度 Rclone FUSE 挂载。
- 关联：[已有挂载目录索引](TD-20261105-01.md) 和[原生 OneDrive 文件类型探测](../directory-browsing-2026-09-08.md)。

## 症状和定位

TwoDrive 重启后，Nautilus 打开 iCloud 根目录长时间显示加载。现场连续 28 秒观察到 FUSE 请求等待和 Rclone 文件属性检查、正文读取。目录列表恢复后，基本属性枚举约 16 ms。隔离冷挂载复现了完整因果链。GIO 请求全属性时，用 `O_NOATIME` 读取无法仅凭名称识别类型的文件开头。原 Rclone 将读取转为 WebDAV GET，目录枚举要等该请求返回。已验证的目录快照继续服务普通列表和属性请求。

## 修复

在 Linux FUSE 收到打开请求时，验证实际调用进程。`gio` 或 `nautilus` 使用只读 `O_NOATIME` 时返回 `ENODATA`，GIO 随后按名称猜测类型。罕见扩展名可能显示通用图标。普通文件打开及其他应用程序使用 `O_NOATIME` 的读取请求仍走原路径。

Linux DAV 便携构建从固定 Rclone 版本编译独立挂载组件。私有 WebDAV 挂载选择相邻的 `rclone-mount` 并启用保护，云端操作继续使用官方 Rclone。旧便携目录仍可以使用原组件。Nautilus 扩展认可同一运行目录内两个确定的可执行文件路径，继续核对 UID、账户缓存根、RC PID、挂载点和缓存命名空间。只认旧路径的扩展曾导致这两个挂载的状态角标消失。

## 验证与边界

在 WebDAV 夹具暂缓 GET 响应时，旧 Rclone 的全属性枚举等待。带保护的组件返回列表且没有正文 GET，普通复制、其他进程的 `O_NOATIME` 读取和写入逐字节校验通过。Nautilus 扩展新增测试覆盖识别两个合法组件以及拒绝不同运行目录和账号缓存的负例。

先前本机以分派程序部署相同 FUSE 补丁。真实 TwoDrive 重启后，Nautilus 从原 iCloud 路径打开约 0.85 秒显示首批文件。跟踪的 GIO 全属性枚举在约 66 ms 内返回 107 项并观察到 5 次探测回退。状态角标修复后再次正常重启，四个挂载恢复，iCloud 和百度实际状态读取恢复，用户确认重新点击 iCloud 时加载很快。实际账号验证覆盖重启、浏览和角标状态读取，写入使用合成数据。

## 防复发

Linux CI 构建并测试该辅助组件，验证生产引擎选择受保护的挂载进程。保留冷挂载、显式读写和状态角标测试，并在更新固定 Rclone 源码时复验。此 PR 基于现有 `dev` 的 DAV 便携构建边界。
