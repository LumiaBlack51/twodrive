# Windows 与 Linux 0.2.24 的本地整合（2026-11-10）

本轮 Windows 桌面在保留多账号和 OneDrive、iCloud、百度、Google 适配的基础上，
完整合入 Linux main `00d797a`（共享核心 0.2.24）与 Windows dev `fe84028`。
运行构建提交由本机程序目录的 `local-build.json` 和设置页记录，属于本机源码构建；没有据此创建 GitHub Release。
设置页分别显示共享核心版本、构建提交与 Windows 开发通道版本，避免把 0.1.7
的开发通道编号误认为仍在运行旧共享核心。

## 界面和挂载策略

侧栏新增“原生同步”。设置新增同步排除规则：Office `~$` 临时文件默认仅保存在
本机，自定义文件名正则同样通过持久本地命名空间读写，不创建云端上传活动。
备份默认按目录名跳过 `node_modules` 整棵子树。修改规则后重新连接挂载生效。
这些设置适用于现有文件管理器挂载及备份；CFAPI 保留其原生临时文件规则。
含有本地排除文件的父目录移动暂时拒绝，避免丢失其本地命名空间。

Linux FUSE 及 GTK/Nautilus 不能直接在 Windows 运行。Windows 的文件管理器挂载
继续使用现有平台实现；界面复用同源业务与策略，不宣称两个桌面逐像素相同。

## CFAPI

生产构建显式启用 `native-sync`，包含 `twodrive-native-dev.exe`。当前桌面入口
支持 OneDrive，使用新的本机 NTFS 目录。准备阶段只读取全盘元数据并建立原生
占位对象，文件内容在打开时按需获取。固定和释放空间使用 Windows 原生机制。
准备前先只读检查父目录是否能证明处于原生同步根之外，未知 HRESULT 会立即拒绝；
不会自动改动卷过滤驱动设置。大账号的首次目录索引和占位对象创建可能耗时，不能用目录尚未完成来推断数据丢失。

桌面使用明确的普通对象模式：特殊服务对象及其子树不进入这个独立根，排除数量
显示在页面中；它们仍可从原挂载或 OneDrive 网页访问。普通对象仍经过严格的
Windows 名称、父子关系、重复 ID 和大小边界校验。已拥有的本地投影或文件不能
因后来变成不支持类型而被静默过滤，刷新会拒绝并保留本地工作。
CLI 原有严格模式保留；普通对象策略用 DPAPI schema 2 封存，阻止旧读者忽略它。

准备、启动、停止均绑定账号及配置修订，并验证本根的注册回执与物理身份。
它不接管或注销 Microsoft OneDrive、其他提供者或原挂载的同步根。
手动启动后随桌面应用恢复运行；“安全停止原生同步”关闭自动恢复意愿。
退出应用会安全停止子进程，保留目录和恢复意愿，下次打开重新验证后恢复。
云端变化每 30 秒检查，固定/释放每 10 秒检查；单轮耗时会影响实际周期。

## 验证与边界

本轮已通过共享核心/后端/完整性 140 项、桌面后端 182 项、原生相关契约 137 项、
Flutter 113 项。环境忽略项与平台跳过项不计入通过数。Flutter 静态分析、严格
Clippy、格式及本地包版本锁检查通过。

实际 Windows CFAPI 的生成夹具通过捕获写入、创建/改名/删除/重启、固定/释放/
重新读取及脏数据保护，云端为模拟实现。真实账户的元数据、根建立、常驻与
应用恢复结果分别记录在本机验收报告；不把生成夹具算作真实云端写入验证。
SMB 保持只读契约，没有真实服务器验收。所有原网盘配置、账号绑定与未同步
工作按最小范围保护，并保留一套已验证回退程序。
